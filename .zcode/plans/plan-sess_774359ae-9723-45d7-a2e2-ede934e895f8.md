# MyBlog 重构方案（v2：改为自有服务器部署）

## 已确认的决定

| 项 | 选择 |
|---|---|
| 技术栈 | VitePress，1.1.0 → 1.6.4，重写主题层 |
| 部署 | 腾讯云轻量（新加坡）+ 自有域名 + Caddy + GitHub Actions |
| 评论 | 全部删除 |
| 外观 | 赛博朋克，重新设计 |
| 运维 | 你接受，但要求"尽量少碰服务器" → 部署侧全部脚本化 + 自动化 |

## 为什么是 VitePress（调研结论）

VitePress 1.6.4 是当前稳定版；2.0 停在 alpha.20（2026-09-04），一年多没有稳定日期，但它的 CJK 排版改进（`markdown-it-cjk-friendly` 默认开启）值得日后单独升。同类里 Astro 7.3.3 生态最健康，但数学公式有已知问题（换 Rust 渲染引擎后行间公式会被代码高亮吞掉，而你有 57 个行间公式），且主题要从零搭；Hugo 部署最简单但主题得写 Go template；Zensical 还是 0.0.63。Nextra（14 个月没发版）、Fumadocs、Hexo、Docusaurus、MkDocs Material（2026-11-05 EOL）已排除。

- 别人的残留：`editLink`/`socialLinks` 指向 fzdwx、RSS 的 `baseUrl`（现在是 `vitepress-blog-theme.vercel.app`，等于你的 feed 在给别人域名做广告）、`index.md` 里 fzdwx 的头像
- 部署遗留：`depoly.sh`、`.github/workflows/update.yml`、`genfeed.yml`、Go 工具（`main.go`/`go.mod`/`go.sum`/`justfile`）
- **同时删掉 `links.md` 友链页和空着的 `qa.md`**（`Qa.vue` 找不到任何 `layout: qa` 页面，现在就是空页）。舍不得友链页的话说一声，我改成纯静态列表保留。

**修正**：
- `base: "/MyBlog/"` → `"/"`，并修掉 `src/utils/index.ts:39` 硬编码的 `path.substring(7)`（这个 7 正好是 `/MyBlog` 的长度）
- favicon：544KB 的 `.ico` 换成新设计的轻量版本
- 依赖升级：VitePress 1.6.4（牵动 vite 4→5.4、vue 3.4→3.5、shiki 2）、`@vueuse/core` 9→12、Tailwind 保持 3.4（不在重做视觉时叠加迁移，升 4 留作后续）

**⚠️ 风险最高的一步**：主题大量 import 了 VitePress 默认主题内部组件（`VPNavBar*` 9 个、`VPDoc`、`VPFooter`、`useSidebarControl`），1.1→1.6 这些内部件可能变过。所以顺序是**先只升依赖、跑通现状并逐页对比**，确认没坏再进阶段 1。

## 阶段 1：写作体验改造（你的核心诉求）

**新的内容约定** —— 分组就是目录名，文章就是子目录里的文件：

```
content/
  index.md / tags.md / archive.md / about.md   ← 站点页
  TypeScript/Generic.md                        ← 文章，URL = /TypeScript/Generic
  Math/Vector.md
```
Loader 用 `./content/*/*.md` 取文章，`content/*.md` 是站点页。配合 `cleanUrls: true` 去掉 `.html` 后缀。**一次 `git mv` 把 49 篇从 `content/docs/<组>/` 上移一层**，顺手去掉 URL 里多余的 `/content/docs/` 前缀。

**元数据全部自动推导**（`src/utils/content.data.ts` + `config.ts` 的 `transformPageData`）：

| 字段 | 来源 | 现在的问题 |
|---|---|---|
| title | 正文第一个 H1 | 现在必须手写且和 H1 重复 |
| group | 目录名 | 自动修掉 JavaScript/Javascript、数学/Math、git/Git 三处目录与分组名不一致 |
| date | frontmatter 优先，缺失取 git 首次提交时间 | 49 篇里 3 种日期格式混用 |
| summary | 正文首段纯文本 | 现在缺 summary 时拿整篇文章当摘要（`gitSubmodule.md` 就是这样） |
| layout | **删掉这个字段** | 现在它既是路由枚举又是评论开关，拼错会静默渲染成光秃秃的页面 |
| sidebar | **删掉这个字段** | 全仓库 0 处代码读它 |
| tags | 唯一保留的手写项，可选 | — |

**配套**：
- `pnpm new "<标题>" [分组]` 脚手架（Node 脚本，不再依赖 Go），只写 H1
- `pnpm check` 校验：没 H1、目录名不在白名单、tags 不是数组、图片引用不存在 → 构建前报错
- 中文搜索：给 MiniSearch 设自定义 tokenize（零新依赖）；不满意再换 Pagefind
- RSS 重写：换成你的域名、去掉"只取 5 篇"的 `slice(0,5)`、过滤站点页、修 author

做完这步，**写一篇笔记就只剩：建文件 + 写 H1 + 写正文**。

## 阶段 2：赛博朋克主题

**架构决定**：继续走"扩展默认主题"（复用搜索/大纲/侧边栏/移动端导航的行为，自己写要 500+ 行），视觉全部通过 CSS 变量 + 自有组件重做。导航栏和侧边栏现在已经是自有的，保持不变。

**视觉方案**（具体化，方便你否）：
- 底色近黑（`#0a0a0f` 一类）+ 霓虹青/品红双主色 + 网格与扫描线纹理
- 标题用等宽/无衬线（工程师感），正文保留霞鹜文楷（已自托管，不改成外部 CDN）
- 卡片辉光边框、hover 霓虹描边、标签做成 terminal 风格 chip、代码块加终端窗口装饰
- 动效只用克制的 CSS transition，尊重 `prefers-reduced-motion`
- **只做深色模式**，不做浅色切换（省一半工作量，也更贴合风格）
- 重做 Tailwind 调色板，删掉遗留的 `cyna-1`、`color1..color10`、`pink1..5` 命名

**先出首页 + 一篇文章页给你看**，风格定了再铺到标签/归档/About/404。

## 阶段 3：内容迁移

一次性脚本 `scripts/migrate.mjs`：删死字段、归一化 3 种日期格式、按目录修正 group、上移目录。

手工处理的少数几处（都是真问题）：
- 2 处 `:::info` 标题里含公式（`:::info 证明 $\sin^2\theta + \cos^2\theta = 1$`），正则转换会破坏，手工改
- 13 个无样式的 `alert alert-*` div（3 个文件）→ 换成真 callout，这是**质量提升**不是回归，它们现在渲染成没有结构的纯文本
- 1 处坏内链：`LLM_OMC.md:658` 硬编码了 `/content/docs/AI/PromptEngineering.html`
- 可选：48 张外链图（beekka 32、ruanyifeng 16）下载进仓库，避免原站挂了图就没了

注意：有 15 篇（Webpack/Javascript/Vue/Git）共享同一个手写日期 `2021-1-02T13:54:36+08:00`，迁移时保留原样。想让它们按 git 真实顺序排的话，我用 git 时间替换。

## 阶段 4：部署（腾讯云轻量 新加坡 + Caddy）

**目标：你只碰服务器一次，日常只 `git push`。**

一次性引导脚本 `deploy/bootstrap-server.sh`（在服务器上跑一次）：
1. 建无 sudo 权限的 `deploy` 用户 + `/var/www/blog` + 正确属主
2. 装 Caddy（官方 apt 源），Caddyfile 只有 4–6 行：域名、root、`file_server`、gzip/brotli、静态资源长缓存头 —— 自动 HTTPS 签发与续期
3. 装 fail2ban + ufw（只放行 22/80/443），并提醒你在腾讯云控制台**手动放行 443**（默认只开 22/80，这是最常见的"看起来是 Caddy 坏了"的坑）
4. SSH 加固：禁密码登录、禁 root 登录
5. 装 `unattended-upgrades` 自动打安全补丁（把"每月手动打补丁"变成零人工）
6. 生成 ed25519 部署密钥，公钥写进 `authorized_keys` 并用 `restrict,command="/usr/bin/rrsync -wo /var/www/blog"` 锁死（不能用裸 `command=`，rsync 需要 exec `rsync --server`）

GitHub Actions `deploy.yml`：checkout → Node 20 + pnpm → `pnpm build` → rsync 到服务器。密钥经 base64 编码存 secret（避免尾换行被吃掉导致 `error in libcrypto`），预置 `known_hosts`（避免首次连接交互卡住），加 `concurrency` 防并发部署。**触发分支修正为 master** —— 现在写的是 `main`，和实际分支不匹配，等于自动部署从来没生效过。

**带宽优化**（你是共享带宽的轻量套餐）：105 张图转 WebP（23MB → 约 6–8MB）+ Caddy 长缓存头。如果实测首屏慢，这是最有效的免费手段。

**线路风险与退路（重要）**：
- 先去控制台确认你的实例在**新加坡一区还是二区** —— 一区走 CN2 GIA、二区走 163，实测差距很大（二区晚高峰可飙到 120ms+）
- 测速要**分运营商**测（移动最好约 65ms，电信 58–180ms 波动，联通最差 93–220ms 常绕美日），用 itdog 多节点
- 如果晚高峰不理想，两个杠杆：① 部署脚本写成可切换的，把同一份构建产物再发一份到 Cloudflare Workers，切 DNS 即可（10 分钟，免费，130–220ms 稳定）；② 买"优选流量包"（专线，但**锐驰型实例不能用**）
- 顺带的好处：服务器上以后想加东西很容易（图床、Waline 评论、自建统计），这是纯静态托管给不了的

## 阶段 5：验证清单

`pnpm build` + `pnpm check` 通过 · 产物里所有站内链接和 105 张图片都能加载 · RSS/sitemap 是正确域名和条目数 · 数学公式回归（Vector + TrigonometricFunction 两篇共 57 个行间公式） · 中文搜索实测（搜"闭包"、"垃圾回收"） · 移动端 · 服务器侧确认 Caddy 证书签发成功、HTTPS 可达、缓存头生效、443 已放行 · 部署后从大陆多节点（分运营商）实测首屏时间

## 执行顺序

阶段 0 + 依赖升级先做（把地基弄干净、确认升级没搞坏现状），然后立刻做阶段 1 的推导层和 `pnpm new` —— 你最快能体验到手感变化。主题设计排在其后，因为它依赖前两步的稳定结构。部署放最后，但 `bootstrap-server.sh` 可以先写好给你，你有空的时候执行。
